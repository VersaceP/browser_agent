# Builder 截断恢复与独立页验证

更新：2026-10-14。对应失败任务 `1e7de846aa2143feadddf40aa33175d3`。

## 已确认的原因

原记录最后两次 `read_source_resource` 均成功。随后模型返回 `rawStopReason=max_tokens`，输出 30,000 token、没有工具调用；Tau 将该响应标记为 `length` 并结束本轮。Builder 原先在任何循环返回后调用 `_finish()`，缺失 `SKILL.md` 的后续检查覆盖了真实停止原因。

这次只写入辅助文件，没有创建测试页、执行 Workflow 或调用完成工具。不是 WebCross 执行失败，也不是任务步数上限。原任务用时约 19 分 43 秒，17 次构建模型调用和 1 次压缩；cache_read 1,730,688、cache_creation 0、uncached_input 496,407、输出 91,671。

## 现在的行为

- `length/max_tokens`：原响应留在会话记录；截断工具调用保留“未执行”回执。在同一个 AgentHarness 和输入游标中加入协议恢复事实，继续处理剩余工作，不重放已完成动作。
- 下一次请求及压缩使用截断响应的协议投影，保留工具 ID/结果配对，不把不完整推理当成完成回答重放；持久化原响应不删除。
- 输出截断、模型错误、取消分别记录真实原因、响应 ID 和模型输出用量。终端显示发生了截断及恢复动作。
- 没有显式完成工具的普通结束或模型错误，返回 `incomplete`，保存草稿索引、文件和恢复命令；即使旧草稿结构完整也不会被自动验收。
- 提供方异常保留原异常。任务失败或用户中断后可以通过当前 CLI 的 `/resume <Builder任务ID> [建议]` 继续。
- 没有新增任务轮数上限、自动业务判定或单站点门禁。普通成功响应不增加模型轮次；截断恢复会产生后续模型请求，需要在真实可比任务中评估成本。

## 草稿和 Workflow 共用的验证

`runtime/program_validation.py` 提供当前源码/阶段合同匹配、阶段判断及证据归属服务。Workflow 保留自己的状态存储；草稿用 `coding/validation.json` 适配同一服务，没有新增模型角色、第二份可编辑源码或合并步骤。

| 工具 | 草稿入口行为 |
|---|---|
| `create_workflow_test_page(fleet_id,url)` | 获得任务授权后，在指定 Fleet 新建独立页；读取历史日志不自动授权操作来源页面 |
| `run_skill_trial` | 固定草稿确切源码快照，通过现有 Skill 执行器运行；保留测试页独立检查点 |
| `inspect_trial_page` | 使用共享原生执行器观察测试页，记录原始回执 |
| `read_validation_receipt` | 读取草稿、自有 trial 或用户明确引用来源任务的证据；拒绝无权引用 |
| `record_workflow_validation` | 模型记录 verified/needs_work/blocked/not_applicable，绑定当时源码与合同 hash |
| `read_draft_execution` | 同时返回确切执行证据和 `stageValidation`；没有当前匹配判断的阶段保持 unassessed |

独立页在 `coding/test-pages.json` 记录创建回执、Fleet 和身份；授权附加的已有页明确标为非新建页。恢复任务时核对保存页面仍属于原 Fleet。用户 Fleet 不会被 Builder 清理关闭。相同 URL 不等于相同登录、业务对象或表单状态，模型仍须观察并建立起点。

代码变化后，旧源码判断成为历史证据；仅文档变化不使未改程序的判断失效。改变已执行阶段的源码不会隐式重放，仍须核对已发生效果。Browser 补救不证明未执行代码通过测试。是否需要继续验证、选择哪些输入变化和前置条件由模型结合目标判断；哈希匹配不证明业务成功。

客观边界沿用页面/Fleet 身份、源码身份、证据归属及权限校验。新页不能是创建前已有页面；不一致时保留原回执并返回绑定错误，由模型重新观察/选择页面。该检查适用于所有站点，不判断字段和业务路径。
