# HITL 终端意见

交互式终端运行时，成功请求 HITL 后会显示暂停页的 pageId、原因及输入提示。输入意见并回车，例如「选 A，只采集第二页可见第 30–32 位」，Harness 会显式调用 `Hitl.resolvePause`，确认页面状态，将原文作为当前 worker 的独立 user 消息加入下一次模型请求。否定意见、范围修正同样有效；解除控制暂停不等于同意原操作。

登录/验证码仍在浏览器处理，不要把密码或验证码输入终端。页面加载、导航等通知触发原有恢复验证，验证通过后解除暂停；刷新本身不证明验证成功。普通业务澄清不会启用页面刷新自动解除；也可使用 WebCross 的 Confirm and continue，但该按钮不提供文字答案，不能替代 A/B/C 的选择。

当前兼容协议没有新增 Hitl.requestPause 字段。Harness 通过 reason/purpose 中的登录、验证码、authentication、challenge 等词区分浏览器协助和普通澄清。模型应把问题和选项写清楚，避免在普通业务问题中混入无关的登录/验证码描述。

多个 worker 暂停时，终端输入按顺序显示并绑定当前提示的 pageId；其它页的浏览器事件仍可独立处理。空行不解除暂停，单次意见上限 8000 字符。超时、任务取消或浏览器恢复时撤销终端监听；POSIX 终端尚未提交的输入会丢弃，避免混入下一个任务。EOF、非交互 stdin 或不支持终端监听的环境保留浏览器事件恢复途径，不读取管道中的任务文本。

意见进入任务上下文及既有记录机制，不应包含凭据。恢复后仍需重新观察页面、刷新元素目标。网络错误、页面关闭或解除失败不能伪装成恢复成功，意见仍保留在等待结果中供模型报告。
